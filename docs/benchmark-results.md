# Before/after benchmark (kinematic model)

Generated by `tools/BeforeAfterBenchmark.java` (run `tools/run-tests.sh`). v1 numbers come from line-for-line ports of the original methods in `tests/LegacyV1.java`; v2 numbers run the real v2 classes. Both drive the same ideal differential-drive model (Pioneer 3-DX wheel radius 9.75 cm, track 33 cm, 32 ms steps). The model has no inertia, slip or box physics, so treat these as measurements of the control logic, not of the Webots simulation.

The whole-mission rows run a line-for-line port of v1's `main` loop (`tests/LegacyV1Mission.java`) and the real v2 classes from the world's start pose, with the same waypoints and gripper timings (checked by `RoutesTest`). On the ideal model v1 never gets past the box-clearing route. It turns at full speed, about 5.4 deg per step, but stops only when its whole-degree compass reading is strictly within 3 of the target: a window about 5 deg wide, and only 4 deg at 0 deg, where the check doesn't wrap around 0/360. A window narrower than one step can be stepped over forever, and that happens on the 5th leg, which heads for 0 deg. v2 slows down near the target and compares headings across the seam.

## With motor lag and wheel slip

The same checks on a less ideal robot: every wheel command takes effect 2 steps (64 ms) late, and turns achieve only 70% of the ideal rate. Neither version was tuned for these numbers.

| Check | v1 (before) | v2 (after) |
|---|---|---|
| Turn-in-place: finishes within 1000 steps (6240 start/target pairs) | 100.0% (6240/6240) | 100.0% (6240/6240) |
| Turn-in-place: mean steps when it finishes | 25.6 | 29.9 |
| Turn-in-place: worst final heading error when it finishes | 3.0 deg | 3.0 deg |
| 360-degree jar scan: rotation actually covered | 188 deg | 371 deg |
| Scan finds a jar 1 m away, 45 deg right of the starting heading | no (blind spot) | yes |
| 530 cm leg starting 2.9 deg off: distance from waypoint at the end | 26.8 cm | 0.6 cm |
| Whole mission (walls and wooden boxes are solid; no box physics) | 0/5 jars, never finishes: stuck from 47 s driving to (-210, 122) (leg 8 of 15 of `hardcodedPathPushing`), blocked by wooden box(2), still at it when stopped at 3200 s | 5/5 jars, 788 s simulated, 0 stalls, 0 turn timeouts |

With lag and slip, v1's turns do finish, but each one overshoots: the motors keep turning for the lag after v1 stops them. v1 drives every leg without steering, so it drifts off its route, drives into an obstacle, and with no stall detection pushes against it until the run is stopped. Where that happens depends on the details, so the next section varies them. v2 steers on every leg and gives up on a blocked leg after a few seconds.
